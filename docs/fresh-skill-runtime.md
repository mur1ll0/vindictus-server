# Detached creation skill phase

M15.1b.2e.10b.13 supplies a concrete runtime for the admitted, unpublished default-skill phase and integrates it with PostgreSQL. It creates a separate context with no loaded equipment, frontend connection, observer proxies or CacheUpdated delegates. It exposes no attachment/load operations and never attaches or resets an existing actor. Completion covers this skill phase only; it is not completion of CharacterEntity/Join/Login, title/status handling, ItemProxy, Summary, lifecycle or TCP Create.

The recovered StatManager constructor initializes SetBonusStat and base stats, while EquippedItemInfo, ItemStat and FinalStat remain null. CalculateItemStat(null,null) retains the null equipped collection and returns before item/weight providers. CalculateFinalStat returns before stat application, INT/AP callbacks or stat notifications. PushAPMessage, PushSkillList and PushUpdateStat return with no FrontendConn; APMax, clock-dependent message construction and serialization remain inside that guard. GuildScore is disabled by the source-bound initializer Profile. Observable.Updated sees zero proxies and a null event delegate, with no dirty revisions or synthetic notifications to add.

The dispatcher still performs the ordered rank/RequiredAP/argument cache changes. The concrete runtime executes the guarded calls. Its AP manager keeps the constructor BonusAPTime=-1, AP and LastAPUpdate unchanged. The actual Meditation ID is rejected before logs, even if its metadata flag claims otherwise. General Meditation, loaded-equipment and connected/observed actors are outside this admission. The source-bound private profile passes: two grants, no Meditation, one item-skill callback, no stat-skill callback. The private probe uses a synthetic ID/time and reports only aggregates; it opens no database and publishes no actor.

save_fresh_detached uses the same transaction, owner/revision/CID lock and timeout as the existing skill writer. It requires completed base stats (dirty=false), a new local row (legacy rowversion absent), initial AP/used AP zero, exp/play time/selected title zero and no existing skills. The existing synthetic first-Fiona ownership/class/level/status restrictions also apply. A separate runtime/cache is built under that lock and used between each independent skill log and the single skill Submit. AP stays clean, so there is no AP UPDATE or datetime conversion on write: the original SQL 1/300-second timestamp is preserved exactly. The returned FreshOutcome has its skill callback debt cleared and retains the resulting cache/runtime. This does not certify the surrounding actor or creation transaction.

Fresh replay is refused before another log rather than returning an unconstructed actor. Existing storage/custom-callback entry points retain their replay behavior and explicit runtime debt. On callback or late SQL failure, pending skill rows roll back; already committed independent logs remain. The local fresh context is not returned on failure. Outer creation cleanup/reconciliation must still be composed; this entry point must not be used as an automatic retry/resume mechanism.
