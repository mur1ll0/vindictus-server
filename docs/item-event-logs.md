# Item event logging components

Migration23 adds ItemLog01/02 (18 source columns) and ItemLedger01/02 (15 source columns), preserving source nullability and technical types. No primary key, foreign key or journal/item uniqueness is invented. ItemLog has nonunique journal/time/rowversion indexes. Ledger has the source unique original-rowversion index; newly written events leave that field NULL. Historical log preservation remains required for the complete migration.

`domain::item_logs` models LogData snapshots and the recovered ItemLogManager Add/SetAfterCount/Write preparation. Numeric fields and opaque UTF16 classes retain their source bounds. Default creation ledgers use GiveItem2/CreateCharacter23; source failure messages use OperationFail0 and SimpleLogData.From(str), with itemID−1/count0/five zero values/NULL bundle count. The source GiveItemRequest projection keeps itemID−1 and the request properties captured before item generation, rather than replacing them with the generated item identifiers/colors. Computing those requests and their actual event sequence during delivery is a later integration dependency.

Automatic logs choose Give/DestroyItem2/3 or Give/DestroySystemItem5/6 according to the system flag and sign of Num (zero follows Give). Only the final queued record receives live owner inventory/shared counts when Write starts. AddSharedItem4/CreateSystemItem4 contributions add to that final shared count with original unchecked Int32 arithmetic and nullable propagation. Disabled Write retains the queue; successful completion of all independent attempts clears it. Cancellation before completion retains it, but delivery may already be unconfirmed or partial: callers must not retry blindly. This is target async cancellation policy; the original actor is synchronous.

LogInfo captures process DateTime.Now during Add. Its persisted Time is the recovered SqlClient datetime parameter conversion to exact 1/300-second units. Database routing samples GETDATE separately; Ledger Time samples its SQL table default separately again. The reference SQL civil offset0 and compatibility100 are measured. Future runtime integration must explicitly supply the process civil clock, not infer it from the SQL offset or substitute UTC silently.

LogInfo.Write attempts even journal−1 and does not check DisableLogging. AddItemLedger/AddSimpleLog skip journal−1 and honor DisableLogging. The original AddItemLedger SQL also suppresses event18. Each row has its own context and caught errors; later ledger rows still run after a failure. Writers use bound SQL and sanitized diagnostics,5seconds per row and15seconds per batch, maximum4096records. Timeout indicates an unconfirmed attempt. Logs are independent of inventory transactions and are not rolled back by a later inventory failure.
