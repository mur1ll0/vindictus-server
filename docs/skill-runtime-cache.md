# First-Fiona skill arguments, caches and callback boundary

This stage recovers the cache data needed before connecting the full initializer. The private source-bound profile now carries the selected SkillArgumentInfo keyword/value rows, not just their count and source digest. It preserves nullable provider fields and raw UTF-16 keywords. Missing arrays, count mismatches, odd/oversized keys and excessive rows are refused. Existing profiles must be regenerated and their Framework feature reference rebound; no missing arguments are silently interpreted as an empty set. Original SQLite/configuration/state files remain read-only.

The domain cache follows the original single-skill LoadBaseSkillRank, OnSkillRankChanged prefix, UpdateSkillArgument and Arg. A missing final SkillRankInfo removes the argument dictionary; an empty result creates an empty dictionary. Arg returns the supplied default only when the entire skill dictionary is absent. An unknown keyword in a present dictionary returns zero. Keys compare ordinally and case-sensitively. Duplicate/null keys or null values fail dictionary construction without replacing its previous contents. Rank and required-AP changes that precede failure remain in memory.

The original rank event adds its delta twice: LoadBaseSkillRank updates SkillRankSum, then OnSkillRankChanged adds to-from again. Both unchecked Int32 operations are retained, including overflow; the port does not repair that source behavior. Required AP uses the already recovered positive-next-rank value or -1. Normal profile admission continues to exclude meditation, active/SP grants, unlock-story and status-effect branches. Final-rank/provider resolution is a caller responsibility; general item-rank boosts and full manager reconstruction remain pending.

The storage writer exposes save_with_callbacks. For each prepared grant it attempts the independent skill log, invokes the caller-owned callback and then advances to the next grant. All skill rows Submit after the loop. A callback failure stops subsequent logs and rolls back skill rows, while prior independent logs and in-memory mutations survive. Logger failure still allows the callback. A late Submit failure retains earlier logs/cache effects. Exact stored replay invokes no callbacks. The existing storage-only API remains explicitly incomplete. Even a successful supplied hook leaves runtime_callbacks_required=true: a generic hook does not certify Stat/AP/observable/entity effects.

A Framework x86/x64 oracle runs 120 synthetic cases per architecture using the original four methods. Final-rank/provider, guild/list/AP and actor dependencies are instrumented; synthetic skill IDs exclude meditation. It checks missing/empty dictionaries, ordinal keys, nulls, duplicates, removals, partial failures and Int32 overflow. Existing GiveSkill/RecalculateRequiredAP differential fixtures remain in the full gate. Three new native PostgreSQL scenarios verify per-log execution, replay, early callback failure, logger failure and late Submit failure. An isolated diagnostic reads the real private profile: two skills/five arguments pass through the Rust cache with synthetic allocator/clock and no database/client execution. No private values are published.
