# Character load and empty equipment state

The source loads CharacterBaseLoadInfo into a dictionary keyed by byte Character and Int32 Level. GetMediumLoadWeight returns the matching CLR Double or -1 when either key is absent. GetHeavyLoadMultiplier returns the exact Double literal 1.2. The private initializer projection now preserves the selected first-Fiona Double as 16 canonical hexadecimal IEEE bits, validates dictionary uniqueness/provider types and pins the original row descriptor. The Rust reader requires the new field and admits finite inputs only; it never supplies zero for missing data.

State.recalculate recovers CalculateItemStat for a proven empty equipped collection. Non-null SetBonus replaces its previous value; a new known empty collection replaces the previous collection. Null inputs retain prior state. With no known collection, the method stops before item effects or load lookup. Otherwise it copies set bonus to item stats, sets weight to zero and creates empty armor maps, then queries the base load. A query failure retains those item changes and leaves previous medium/heavy/penalty fields intact. This state has no independent SQL writer.

Medium load adds the cached skill_weight_mastery/max_weight_increament_bonus Int32 argument. Heavy load multiplies the stored medium field by 1.2. The original penalty formula and CLR NaN-to-Int32 result are retained: a zero threshold produces Int32.MinValue rather than an invented zero penalty. Explicit Framework x86/x64 arithmetic also retains the measured extended exponent range in the x86 numerator for very large finite base values whose stored heavy field is infinite. These extreme synthetic penalty results differ across architectures; the ordinary weight/threshold calculations were checked independently.

The Framework oracle executes the original CalculateItemStat, ApplyMediumLoadSkills, GetMediumLoadWeight and GetHeavyLoadMultiplier on 640 synthetic cases per architecture. The empty-item provider, owner, set-stat sentinel and base-query failure boundary are owned instrumentation. It covers absent/retained/replaced collection and set inputs, missing source keys, positive/negative/subnormal/extreme Doubles, signed/overflow-sized Int32 bonuses, all output fields and provider calls. The original full empty ApplyItemSkills copy was separately checked in the preceding stat stage; this oracle does not execute nonempty equipment branches.

A private diagnostic compares the actual base-load profile and initial two skills/five arguments with the original Framework methods before and after each cache update, for both architectures. It retains known empty Gear across repeated calculations, uses synthetic set bonus, opens no database and emits counts/booleans only. Inputs and results remain in the existing ACL cache.
