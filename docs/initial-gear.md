# Initial unequipped Gear

The fresh Fiona creation path contains equippable items in bag/cash storage, but their Equippable.Part is NULL. Item.IsEquipped checks that part, not simply the equipment type or collection. The initial factory model and insert-only writer preserve this NULL; the customization integration test verifies it. This corrects the preceding stage's assumption that five equippable items implied nonempty Gear.

The existing appearance package now preserves EquipPartInfo.IsConsumable and binds the original Gear, EquippableSlot, ItemContents, item/storage models, HeroesContentsLoader and both SQLite providers by SHA-256. The export CLI checks those files before and after its readonly snapshot. Older packages without this required metadata are refused; the preceding private package is retained as a backup.

IsConsumable is declared BIT in the real SQLite. The original providers on Framework x86/x64 return System.Boolean and throw on GetString. HeroesContentsLoader catches that exception and keeps the Boolean value. The owned readonly measurement verifies all 201 rows. Export therefore admits canonical integer 0/1 storage with declared BIT, separately from the string Boolean profile of CustomizeItemInfo.IsCash. Unmeasured storage is refused rather than coerced.

initial_gear::Projection groups slot metadata in source insertion order. Each group's FIRST IsConsumable chooses quick slot versus Gear. For Gear, costume-part deduplication is local to the slot, including -1 and 2; decorations remain distinct source rows. Locked/disabled empty slots still emit placeholders. The original empty-slot initializer uses CostumeSN=-1, colors/numerics/stats zero, empty item/equipment class strings, Effect=null and IsAvatar=false. The typed EmptyInfo represents this initializer; it is not a general equipped-item DTO or wire serializer.

ToSetBonusInfo sees no equipped items and returns zero known stats and an empty skill dictionary. The AvatarSlotBonus lookup still validates its flag, but num=0 prevents the avatar-set query for either flag outcome. Avatar lookup cannot find an equipped item in this path. A missing provider is never substituted for a loaded empty Gear.

apply_item_stats preserves the placeholder armor entries and source partial outputs on a duplicate part. Treating the result as an empty IList would lose those entries. item_stats is the convenience success-result API; use the out-parameter API when retaining source partial failure state.

Customization preflights the bound metadata before delivery journal/inventory effects, admits only the fresh PreparedInventory contract, and exposes Outcome.gear alongside the existing inventory/appearance result. PreparedInventory denotes new rows whose writer inserts Part=NULL; this is not a read-side test of arbitrary stored inventory. The source first-Fiona ownership/provenance/revision guards remain in delivery. Invalid slot metadata prevents delivery; existing replay/reconciliation behavior is retained. The owner constructor journal remains an earlier, separate obligation. Returning the projection does not certify that stat/AP/observable callbacks have executed.

Source sets with duplicates, nonempty Gear, avatar overrides, locks/quick-slot state and general set loading remain full-migration work.
