# Creation item journals

Migration22 and `infrastructure::item_journals` preserve the two independent source journal identities and implement the bounded `CustomizeCharacter` journal attempt. They do not implement ItemLog/ItemLedger, the complete initializer or TCP Create.

The recovered `AddItemJournal` procedure calls **getCharacterJournalID**; `ItemLog.GetJournalID` instead calls **getItemJournalID**. Their source identity seeds are4419625 and611635750 respectively, increment1. Both source allocator procedures insert a counter row, obtain SCOPE_IDENTITY and roll back. Consequently no counter row is preserved for that allocation, but the identity remains consumed. PostgreSQL uses separate noncycling BIGINT sequences and does not reclaim an allocated value on rollback or journal insertion failure.

The private stdin importer preserves each original `sys.identity_columns.last_value`, including the explicit uncalled/null state. First initialization publishes both bindings and transactional sequence restarts together. Replay verifies the exact bindings and minimum sequence position without restarting either sequence. Changed source bindings or regressed sequence positions are rejected. This is target bootstrap policy, not a new legacy procedure. Input is strict, bounded to4096bytes, and private values never appear in summaries. The operational exporter requires the two measured non-null source identities, reads them twice and checks the reference did not change. It never invokes a source allocator.

GetJournalID honors DisableOperationLogging; AddItemJournal honors DisableLogging. These are separate switches and must be supplied from the validated feature profile during future composition. Disabled or failed calls return−1. Exceptions are caught with sanitized diagnostics. Each attempt is bounded to5seconds; timeout means delivery may be unconfirmed, not proof of absence. No retry is performed internally.

AddItemJournal routes by original DATEDIFF(day,2011-01-01,GETDATE()) parity and separately samples the table default time. The already measured source civil clock offset0 and compatibility100 conversion are reused. ItemJournal01/02 preserve ID primary keys, time indexes and unique original rowversion indexes. New rows leave the original-rowversion field NULL, consistently with earlier log migrations. No fabricated rowversion, character foreign key or cross-partition uniqueness is introduced. Historical journal/log rows remain a full-migration dependency; current Create does not read their history.

Tests use synthetic identities in isolated PostgreSQL schemas: independent allocation, concurrent consumers, disabled calls, correct source counter selection, category/time/NULL fields, exact replay, transactional bootstrap rollback, failed insertion with consumed ID, exhausted sequences and conflict rejection. Existing SQL clock/parity tests cover synthetic datetime boundaries. Original SQL/C# paths and hashes are recorded in sanitized evidence; no proprietary bodies or private counter values are added.
