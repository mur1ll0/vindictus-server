# AP manager transitions

The domain state ports APManager.UpdateAP, CalculateBonusAPTime, UseAP and GiveAP. CharacterInfo AP and LastAPUpdate are explicit inputs; a fresh manager starts with BonusAPTime=-1. Its caller owns the character transaction. There is no independent AP writer or successful creation response.

UpdateAP samples UTC and the maximum only for a positive interval. It retains the original Double TimeSpan.TotalSeconds conversion, truncating CLR Int32 conversion, unchecked AP arithmetic and Int32 multiplication before TimeSpan construction. It advances LastAPUpdate even when AP is already capped. A DateTime-range error occurs after AP mutation and leaves that mutation in memory. Recalculation with interval zero first replaces LastAPUpdate; a later interval-provider failure retains the replaced date and previous interval. Disabled intervals do not sample UTC or the maximum during UpdateAP.

UseAP updates accumulated AP before checking the request. GiveAP preserves signed inputs, unchecked overflow and repeated maximum-provider reads. The source comparison of an already-overflowed Int32 sum with Int32.MaxValue does not introduce saturation in the port. Guild gain/report behavior is outside GiveAP and remains unported here.

The private initializer now exports APMax. Its accessor requires an exported key and retains lazy source integer parsing, including overflow errors; no real maximum is published. The no-meditation path follows the original CalculateAPTime early return before StatRatio is read. A present meditation dictionary with an absent keyword returns zero from Arg rather than -1, so it is refused by this restricted path. Trained meditation and its floating-point formula remain pending.

The Framework oracle executes the four original AP methods on 448 synthetic cases per architecture, plus three early-return/policy-failure prefix cases. UTC, maximum policy, interval calculator and owner fields are instrumented. Both architecture results are retained and equal for these cases. It covers clock/policy/calculator failures, caps, signed grants/use, overflow, extreme dates, return values and provider-call counts. Rust compares complete resulting state after failures as well as success.

A private diagnostic binds the real initializer, two skills/five arguments and maximum policy, then exercises the untrained transition with synthetic AP/allocator/clock. It opens no transactional database and discloses no private values. Full stat/item callbacks, trained-meditation arithmetic, dirty observables, title effects and applying AP changes inside the same character Submit remain pending. Full migration remains required.
