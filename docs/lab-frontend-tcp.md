# Frontend TCP restrito de laboratório

M13.3d.2b liga a implementação de login local à conexão real, usando o perfil privado preparado na etapa anterior. O listener é loopback, aceita no máximo oito conexões e só admite passports completos da allowlist. A guarda transacional recusa contas sem proveniência sintética antes dos efeitos. Os dados enviados pelo cliente não autorizam identidade, cheats ou bypass. A disponibilidade geral de autenticação no HTTP operacional continua false; este adapter é restrito ao laboratório.

Registro de mensagens e override NGM_disable=1 são enviados conforme as fontes recuperadas. A cifra mantém estado por conexão e processa todos os frames de cada leitura, incluindo mensagens fragmentadas e agrupadas. O perfil candidato PingPong=false é respeitado. As comparações efetivas de SecondPassword/SecondPasswordClear foram acrescentadas ao oracle:20observações x86/x64 em cinco culturas, sem divergência; o primeiro startup recusou a ausência dessa evidência antes do banco/listener. Não se desabilitam flags externas: perfis com dependências ativas não implementadas são recusados antes do banco/listener. NG indisponível conserva o retorno NULL recuperado; journal indisponível conserva o catch da fonte e é registrado como indisponível.

Login admitido executa os efeitos já recuperados, consulta a lista realmente vazia e emite segunda senha/lista/diálogo dormant/CafeLogin. Uma lista com personagens é recusada com reason9 e BannedReason NULL, seguida pelo fechamento em cinco segundos; nenhum personagem é ocultado por uma lista inventada. Ainda não há CreateCharacter, SelectCharacter, PlayerLoader, LoginOk de entrada nem canal MMO. A consulta HomeCafe executa o contrato original, mas a composição posterior de UserInfo continua pendente.

A segunda senha utiliza armazenamento privado, revisão e dono da sessão. Métodos originais Framework foram executados x86/x64 para validar NULL: no modo legado Check(NULL) não corresponde e consome tentativa; Sha512 cai no catch; AccountSha512 concatena o nome com NULL e pode comparar com o hash de senha vazia. A mudança de versão calcula o hash alvo antes da comparação. Set(NULL) conserva o banco e o estado visível, retorna falha -1 e impõe dez minutos em memória. Falhas SQL capturadas por Query mantêm Has sem Ask; falhas internas de Check/Set preservam o resultado recuperado. Não são equivalentes a strings vazias.

A sessão compartilha a reserva contra login duplicado. Conexões iniciais têm prazo absoluto de 30 segundos; escrita e cleanup são limitados. Cleanup de sessão aceita atualiza somente locks IP expirados conforme a fonte, antes de liberar a reserva. Cancelamento libera a reserva sem IO em Drop. O cleanup de falhas de admissão que já encerraram a sessão na camada de aplicação ainda precisa ser retomado junto à composição completa do lifecycle; não se declara todo lifecycle migrado.

Quatro testes TCP Windows sem banco e três testes TCP Linux com PostgreSQL isolado verificam bootstrap, frames, allowlist, recusa sem efeitos, segunda senha, reconnect, duplicata, fechamento e dependência de lista não vazia. Gate completo:213 Rust,68 PostgreSQL executados e19 Python, zero falhas/avisos. Docker build/migrate/readiness/smoke/restart preserva snapshots e um marcador sintético depois do login real e zero usuários importados marcados. O iniciador Windows foi executado com perfil sob ACL e credenciais apenas no ambiente, sem argumentos de senha. O endpoint HTTP da cópia responde200. Logs completos permanecem em.cache/verification.

Esses testes não comprovam compatibilidade do Vindictus1.69EN. O operador confirmou login, registro de segunda senha, tutorial local de Fiona e acesso à criação por Tieve/Say my name. Check não responde e Create termina em Response from server Delayed. Isso não comprova batalha no servidor nem personagem persistido.
