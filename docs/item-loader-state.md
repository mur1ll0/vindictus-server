# Initial item-loader associations

This stage removes a data-preservation blocker before the first character inventory can be loaded. It does not implement complete ItemOwner, Save/Undo, Player.LoadPlayer or TCP Create.

The recovered DBLoader supplies QuickSlot and ExpandSlotInfo to Gear before LoadItems. ManufactureManager subsequently reads Manufacture and ManufactureRecipe, and ItemOwner.Load then reads NewRecipe. Treating any missing table as an empty result would omit actual source data. The fresh source contains 261 QuickSlot rows and zero rows in each of the other four tables.

Schema 31 preserves all twenty fields, five primary keys and five identity counters. QuickSlot references Character and NewRecipe references ItemCollection, with the original update/delete cascades; the other three source tables have no foreign keys. UTF16 is stored as raw bytes, including unpaired code units and trailing spaces; recipe datetimes retain 100 ns precision. Signed slot, grade and experience values are not normalized. No string comparison or crafting subsystem compatibility is implied by preservation.

The importer checks current column metadata, primary keys, unique indexes, identity seeds/increments, FK mappings/cascades/trust, default constraints and NVARCHAR collation before exporting all rows in a read-only transaction. Empty results are explicitly serialized as arrays after actual row-count checks. Private exports have Windows user/SYSTEM ACLs and remain outside Git. Source hashes are compared before/after import. No legacy service or stored procedure is executed.

Bootstrap is transactional and refuses unmarked data, called sequences or altered uncalled sequence starts. Replay verifies all fields and never repairs data or reseeds identity counters. Later native writes will require an explicit preservation/provenance extension; they must not be silently admitted as source rows.

The initial Gear helper consumes current native ownership, initialized provider state and proved empty quick/expanded slots, inventory and storage status. It reuses the previously recovered, content-bound empty Gear projection under retained locks, without SQL writes or identities. Nonempty associations, partially delivered inventories, stale owners and changed content are refused. The absence guards are admission components, not completed constructors or reusable permission to skip later queries.

Verification includes parser bounds/types, raw UTF16 and datetime2 limits, full-field replay, independent sequence state, late FK failure rollback, refusal of silent sequence reset, original cascade/no-FK behavior, retained SHARE locks, initial Gear admission and stale/content/nonempty rejection. Existing Gear Framework differential fixtures remain unchanged; no wire format or opcode changed in this stage. Final sanitized evidence is in evidence/auth/item-loader-state.json and evidence/verification/REPORT.md. Full logs remain in .cache/verification/item-loader-*.
