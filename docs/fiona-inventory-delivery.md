# Initial inventory delivery components

This stage connects the existing normal empty-inventory composer to source factory logging and an internal save/log coordinator. It does not enable TCP Create or establish real-client compatibility.

`ItemFactory.MakeItem` sets Parent and the shared-authority ID, runs Initialize, calls Loader.CreateItem, captures CreateItem1, then sets the final location and registers the item. Initialize writes Count before Num, so the Num setter does not emit a quantity event in this branch. The new InventoryClock hook runs at the corresponding creation boundary after generated colors/durability. The snapshot still represents a null location/system item; the explicit event detail is CreateItem1. Persistent IDs,counts,colors and durability come from the same prepared inventory used for storage.

Before generation, the composer captures the original GiveItemRequest ledger fields:ID−1,request quantity,colors−1/durability0 and NULL BeforeItemID. Final generated colors/IDs never replace those request fields. Stack counts aggregate the full request in this admitted empty/class-grouped inventory. GetBundleItemCount returns NULL for MaxStack<=1. Positive grouped requests are bounded to4096 before allocation; unsupported empty/nonpositive requests are refused. Process civil time is sampled at each enabled event, separately from allocation/expiry UTC and SQL routing clocks. The disabled logging path never samples the event clock.

The source-bound adapter reuses the existing catalog/stats/colors/profile validation. The coordinator verifies the source-state hash and the owned synthetic first-Fiona revision before journals; it rechecks first-Fiona admission inside storage. It allocates the processor item journal and the independent customization ledger journal. The ItemOwner constructor journal belongs to the earlier entity-load phase and is not fabricated here. After an atomic inventory commit it attempts the queued automatic logs and then the ledgers. Logging failures do not undo inventory. Preparation/storage failure drops pending automatic events and attempts the appropriate original simple failure ledger. Authority/RNG state remains consumed.

Existing identical storage is returned as Reconcile, never as a newly completed delivery or permission to replay logs. Concurrent identical attempts produce one inventory/event set. Interrupted or partially delivered work requires lifecycle reconciliation; this component does not implement durable resumption or complete source Undo/ItemOwner caches. Appearance and subsequent per-skill/title callbacks are not invoked yet.

A real dependency was discovered during private profile validation: the candidate path loads SharedItemManager. Its stack count for an empty shared inventory is0, not NULL. The initializer exporter and reader now explicitly include the distinct DisableOperationLogging and SharedInventory contract keys. Source feature comparisons remain private and instance-bound; no version/value payload is published. The general profile continues to accept the real configuration. Migration24 preserves all4/5fields of ItemShared/ItemSharedStorageStatus,original PKs,nulls and identity (source8/5rows). The restricted loader verifies bootstrap,synthetic owner/revision and absence of both items and tabs for that account before authorizing empty shared counts. Without that proof it returns SharedState before journal side effects. Existing/nonempty shared inventories still require the full loader and remain unsupported. No default empty state is presumed.

The source DBLoader procedures resolve to dbo.ItemShared and dbo.ItemSharedStorageStatus in study_heroes. Their original typed rows are imported privately,replayed and compared after restart; NULL and expired data are preserved without inferred timezone. Source identity last_value is retained transactionally and replay never reseeds it. No source FK or owner/slot uniqueness is invented. The empty-manager count is checked against the original SharedItemManager method.
