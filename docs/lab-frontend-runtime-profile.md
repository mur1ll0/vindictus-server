# Configuração do frontend de laboratório

M13.3d.2a.2 prepara o contexto privado necessário ao próximo adapter TCP. O comando inspect-lab-frontend-profile valida stdin e conteúdo antes de consultar configuração de conexão; não abre listener nem PostgreSQL. Login no jogo permanece pendente.

O parser aceita somente campos conhecidos, no máximo16KiB, um bind loopback nãozero, arquitetura Framework x86/x64 e cultura ASCII explicitamente validadas. Exige correspondência com hashes do conteúdo e configuração ORIGINAIS, região/override nullable, GameCode, ServerCode e CurrentVer. Vinte e quatro declarações de política são obrigatórias; ausência não significa flag desabilitada. NGM_disable precisa estar ativo. Os outros serviços externos ainda serão validados pelo futuro runtime antes dos efeitos.

A allowlist contém de1a8 passports completos ASCII; derivação de identidade, colisões de UID e nomes canônicos são validadas. A comparação usa somente a casing ASCII conferida; prefixo, truncamento de24caracteres e UID não provam pertencimento. Entradas, passports armazenados e buffers de configuração são zerados; nenhum perfil/passport é Debug ou Serialize. O fingerprint deriva hashes originais decodificados, arquitetura/cultura, região/override, versão, códigos, ServiceID/ChannelCode e offset civil explícito. Alterar allowlist, bind ou subconjunto exportado do mesmo conteúdo não abandona marcadores existentes. Fingerprint não é credencial.

prepare-lab-frontend-profile.ps1 lê o original somente para conferir hash e recuperar PingPong=false. Recebe allowlist limitada pelo stdin; grava um arquivo novo com nome aleatório em.cache/private-frontend, sob ACL protegida para usuário Windows atual e SYSTEM, e verifica a herança no arquivo. Diretórios reparse são recusados; nenhum original é alterado. Arquitetura/cultura/ServiceID/ChannelCode são parâmetros explícitos. O perfil candidato usa UTC+8 recuperado da referência, sem inferir timezone deste host. A preparação real foi conferida com uma única conta sintética, sem publicar passport ou caminho privado no relatório.

lab_clock converte SystemTime em DateTime ticks com aritmética checked, precisão100ns e limites dos anos1a9999. DateTime.UtcNow permanece independente; DateTime.Now civil aplica o offset explícito. Conversão para SQL datetime usa a quantização já recuperada. Um harness próprio de DateTime Framework, compilado x86/x64, compara140casos por arquitetura incluindo epoch, segundos negativos, subsegundos e limites/offsets. Não executa serviços legados. As280observações não divergem.

Quatro novos testes cobrem allowlist, perfil/limites/declaracões, estabilidade e mudança do fingerprint e relógio/oracle. Gate completo208Rust/65PostgreSQL executados/19Python, zero falhas/avisos. Inspeção do perfil privado passa no binário Windows e na imagem Linux. Docker build/migrate/readiness/smoke/restart preserva snapshots e zero marcadores reais. SQL Server e originais permanecem somente leitura. Logs completos ficam em.cache/verification.
