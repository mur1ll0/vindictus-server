# Default skill storage and creation event logs

This component prepares the first normal Fiona default skills from the protected initializer profile and persists the admitted rows. It does not complete GiveSkill, CharacterEntity initialization, Create, selection or city entry.

Preparation uses the same EntityAuthority as CID/items and never rewinds its counter. The admitted source defaults are passive, available at level1, unconstrained, without status effects/meditation and without next-rank unlock. The persisted fields are RowID/CID/UTF16 SkillID/rank/locked0/CurrentAP0. RequiredAP for the next rank remains cache metadata: positive source value or−1. Ordered item/stat callback metadata is retained privately. Save requires an owned synthetic first-Fiona revision, the exact imported state fingerprint, preserved Skill/SPSkill identity and exactly the initialized slot0NULL. Conflicting state is not repaired. Exact replay does not duplicate stored rows or log events.

The source logs every granted skill before its SubmitChanges, using a separate context. Source logging exceptions are caught. PostgreSQL therefore attempts these writes independently: failed logs do not abort skills, while failed/cancelled skill Submit does not erase earlier logs. GiveSkill=1 and GiveTitle=2 use journal0 during creation; skill AP and title goal/value are0. No unique constraint on journal/name/title is invented. Source title insertion errors are also caught; the receipt distinguishes that case from logging failure.

Migration21 adds only Skill/Title event log storage. Time retains datetime2 ticks, with source GETDATE quantization and separate routing/default-time samples. The actual reference compatibility level100 and civil offset0 were measured, along with256 synthetic datetime conversions. Original rowversions are not fabricated: legacy_last_update is reserved for original bytes and isNULL for new local rows, following migration16. Historical log preservation, item journals/counters and ItemLog/ItemLedger remain separate dependencies. Log attempts have bounded time budgets; failed counts include unconfirmed delivery after timeout.

The C# oracle extracts ConstraintPassed/GiveSkill/RecalculateRequiredAP and class availability into ignored cache. Its allocator/log/SP/story/callbacks are instrumentation. The public fixture is synthetic:200 scenarios per architecture; Rust compares40 admitted passive grant preparations, source fields and shared allocator chaining. This is not evidence of a full skill subsystem or its callbacks.

The complete runtime must execute each per-skill cache/stat/observable callback in original order between its log and the final Submit. Running callbacks after the storage receipt would change the source order. A false fresh-row callback flag is not proof that an entity is initialized. The success lifecycle and TCP Create remain disabled until the full runtime is implemented and verified.

Validation: generate-initial-skills-fixtures.ps1; measure-character-event-logs.ps1; targeted Rust and isolated PostgreSQL cases; verify.ps1 -DatabaseIntegration; original Dockerfile build, migration, readiness, account/duplicate/nonroot/restart; existing state imports verified after restart. Full logs stay in .cache/verification. No private profiles, raw procedure bodies, original assets or credentials belong in Git.
